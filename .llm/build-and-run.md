# Build & run

## Dev

```bash
./run-dev.sh
```

Runs **both** apps together and tears both down on Ctrl-C. Each is a normal `npm run tauri dev` (installs `node_modules` first if missing):

- `taskscape-main` → Vite on **:1420**, HTTP on **:7420**
- `taskscape-tray` → Vite on **:1421**, HTTP on **:7421**

In dev the two apps are launched by the script, so the main app's `launch_embedded_tray()` is a no-op (the nested bundle only exists in packaged builds).

To run just one app: `cd taskscape-tray && npm run tauri dev`.

## Ports (fixed)

| Port        | Used by                                                              |
| ----------- | -------------------------------------------------------------------- |
| 1420 / 1421 | Vite dev servers (main / tray). `strictPort` — dev fails if taken.   |
| 7420 / 7421 | Runtime HTTP IPC (`MAIN_PORT` / `TRAY_PORT` in `common/src/lib.rs`). |

## Schema changes (the dev loop)

Persistence is **SeaORM** (async queries) over SQLite, with migrations
autogenerated by **Atlas** from a declarative schema. Both are dev-time tools —
neither ships in the `.dmg` (the app embeds and replays the SQL Atlas produced).

One-time tool install:

```bash
brew install ariga/tap/atlas   # migration autogenerator
cargo install sea-orm-cli       # entity codegen
```

To change the schema, edit the "models" and regenerate — run from the repo root:

```bash
# 1. Declare the change (add column/table/index/FK) — the source of truth.
$EDITOR common/schema.hcl

# 2. Autogenerate the versioned SQL migration into common/migrations/.
atlas migrate diff <name> --env local

# 3. Regenerate the SeaORM entities from a DB built at migration head.
./common/gen-entities.sh

# 4. Map any new/changed field in common/src/storage.rs (entity → models.rs).
```

`common/schema.hcl` is the desired schema; `atlas.hcl` is the Atlas project config
(the `local` env). `gen-entities.sh` builds a throwaway `dev.db`, runs `sea-orm-cli`,
and normalizes SQLite's loose numeric typing (`i32`→`i64` millis, `Decimal`→`f64`
ordering keys). The runtime applier in `common/src/migrations.rs` replays embedded
migrations at startup, tracked in a `schema_migrations` table.

**Data policy:** the `0001` baseline started from an empty DB (dev data was
disposable). From `0002` onward, migrations run against real user DBs and must be
forward-only and non-destructive. See [`.plans/orm-migration.md`](../.plans/orm-migration.md).

## Package into one `.dmg`

```bash
./make-app.sh   # → dist/Taskscape.dmg
```

What it does:

1. `tauri build --bundles app` for **both** apps (release `.app` bundles).
2. **Embeds** the tray app inside the main app at `Taskscape.app/Contents/Library/LoginItems/taskscape-tray.app` — so the user installs one app and the main app launches the nested tray on startup.
3. Assembles `dist/Taskscape.dmg` (the app + an `/Applications` symlink).

Bundles are **unsigned**: first launch needs right-click → Open, or `xattr -dr com.apple.quarantine <app>` (recurses into the nested tray helper).

## Gotchas

- Changing an IPC port means editing `common/src/lib.rs` (runtime) and/or the `vite.config.ts` `server.port` (dev) — they are independent.
- The tray's window label is `"main"` — don't confuse it with the main app.
- Rust changes rebuild via Cargo on the next `tauri dev`/`build`; frontend changes hot-reload through Vite.
